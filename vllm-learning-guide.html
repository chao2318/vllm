CHAPTER 01 / 15第 2 天 · 1 小时

模型到底在计算什么

从字符串进入张量与概率

语言模型通常计算 P(下一个 token | 已有 token)。训练调整权重；推理读取这些权重，为当前上下文算出下一步分布。vLLM 主要解决如何高效执行与服务这个推理过程。

概念软件工程视角注意
Token / Tokenizer把文本编码成整数序列的规则与词表可能是子词、标点、字节片段；中文一个字不保证是一个 token。
Tensor 张量带 shape、dtype 和设备归属的多维数组[T,H] 表示 T 个 token，每个 H 维。
Weights 权重加载后长期驻留的参数数组请求共享模型权重，但不自动共享上下文状态。
Activation 激活forward 过程中产生的中间数组随输入变化，生命周期与 KV 不同。
Logits词表中各候选 token 的未归一化分数采样选出 ID，然后解码成文本。

假设词表只有 [猫、狗、车]，logits=[2,1,0]。softmax 变成约 [0.665,0.245,0.090]。temperature=0 通常走贪心选择；正温度用于缩放分数后采样。模型不是从数据库中查出一整段固定回答。

pᵢ = exp(zᵢ / τ) / Σⱼ exp(zⱼ / τ)τ > 0；τ=0 使用单独的贪心分支

一次请求为什么需要循环

给出 prompt，计算第一个输出；把它加入上下文，再计算第二个，直到 EOS、停止规则或长度上限。普通自回归解码中，同一序列存在因果依赖；多个独立请求则可以一起执行。EOS 是结束标记，max_tokens 是生成上限，不保证总能生成到该长度。

CHAPTER 02 / 15第 3–4 天 · 2 小时

Attention 为什么需要历史

用一层 Transformer 建立计算直觉

Embedding 把 token ID 映射为 H 维向量。典型 decoder 层先读取前文信息（Attention），再经过逐位置的非线性网络（MLP）。多个层串联，最后隐藏向量投影到词表，得到 logits。

Token IDs→Embedding→Norm → Attention
+ Residual→Norm → MLP
+ Residual→LM Head
logits

Q、K、V 是隐藏向量乘以不同权重矩阵的结果。Q 表达“我应关注哪些位置”；K 用来计算匹配程度；V 是按权重汇总的内容。因果 mask 只允许位置 t 读取 ≤t 的位置。

Q=XWq，K=XWk，V=XWv
Attention(Q,K,V)=softmax(QKᵀ/√d + mask)V

单头教学 shape：X 为 [T,H]；Q/K/V 为 [T,d]；QKᵀ 为 [T,T]；输出为 [T,d]。decode 的 Q 只有 [1,d]，仍要读历史 K/V，分数为 [1,T]。高效 kernel 可分块计算，不必把完整 [T,T] 矩阵写入显存。

组件用途读代码时关注
Multi-head多组投影表达不同关系Query heads 不一定等于 KV heads。
GQA / MQA多个 Q head 共享较少 KV head降低 KV 成本；GQA 用 KV head 数估显存。
RoPE给 Q/K 注入位置信息位置与前文决定状态，相同 token 不必有相同 KV。
RMSNorm / Residual控制数值尺度与保留跨层信息残差与归一化的实际顺序看 forward。
MLP逐位置的特征变换同样有大量矩阵计算，模型不只有 Attention。

CHAPTER 03 / 15第 5–6 天 · 2 小时

KV Cache：用显存换重复计算

分清 prefill、decode 与刚采样的 token

固定前文的旧位置，不会因追加 token 而改变其因果 decoder 状态。每层保存这些位置的 K/V，下轮只为新输入计算 Q/K/V，再读取历史 KV。这避免每步重复计算整个旧前文。

Prefill 处理 prompt、建立 KV，用最后位置的 logits 采样首个输出。Decode 把刚生成的 token 送进模型，计算下一个输出。KV 避免重复投影与旧位置的层计算，但没有消除新 Q 读取历史 K/V的工作。

无 GPU 演示

跟踪一个 4-token prompt

输入 [11,22,33,44]，固定输出 [51,52,53]。同步、无 prefix hit、无推测解码；数字是教学 ID。

一个重要的 off-by-one

刚采样的 token 已属于输出，但还没作为输入做 forward，通常还没有自己的 KV。无推测与异步时，生成中的请求常有 num_tokens − num_computed_tokens = 1；结束后不需要为最后输出再做一次无意义的 forward。

理想化 KV 容量公式

字节数 ≈ 2 × L × Hkv × D × S × B × bytes

L=层数，Hkv=每层 KV head 数，D=head 维度，S=每条缓存长度，B=并发序列，2 表示 K 和 V。假设完整 Attention、各层相同、单副本无共享；MLA、滑窗、混合模型、多卡分片要另算。

KV 显存计算器

不含权重、激活峰值、CUDA Graph、padding、量化 scale 与管理开销；不是可部署并发承诺。

默认参数每 token 128 KiB，一条 4096-token 序列 512 MiB，32 条约 16 GiB。另算权重：8B 参数 × 2 字节约 16 GB（14.9 GiB），尚未包含 KV。

Python · learn_smoke.py
from vllm import LLM, SamplingParams


def main():
    llm = LLM(
        model="facebook/opt-125m",
        dtype="float16",
        max_model_len=512,
        enforce_eager=True,
    )
    params = SamplingParams(temperature=0, max_tokens=16)
    results = llm.generate(["The capital of France is"], params)
    for result in results:
        print(result.prompt_token_ids)
        print(result.outputs[0].token_ids)
        print(result.outputs[0].text)
        print(result.outputs[0].finish_reason)


if __name__ == "__main__":
    main()

边界数据合同意义

异步是为了减少 GPU 等待 CPU 的空隙

step_with_batch_queue() 管理在途执行。CPU 准备后续步骤时，GPU 可以执行当前步骤。“安排计算”与“CPU 收到完成结果”不同，Request 的 placeholders/in-flight 字段记录这种差异。

因此本页的手算标明同步假设，不能逐字段要求真实异步路径与之相同。V1 引擎和Model Runner V2是不同层次的版本命名，可以同时存在。实际路径要看配置与启动日志。

Scheduler：批处理按轮变化

请求数、token 预算、KV 容量共同约束

静态 batch 等整组完成再接新任务，容易被长短不一的输出拖慢。连续批处理在每轮重新组成 batch：完成者退出，新请求补入，未完成者继续。它减少空槽，但不消除单条序列的因果依赖。

本提交 schedule() 开头说明：统一追赶 num_computed_tokens 与待处理 token 数，不仅靠两个固定的 prefill/decode 阶段。无推测/异步时，可把欠账理解为 len(prompt + output) − num_computed_tokens。

约束控制什么不是
max_num_seqs同时服务的序列数量单轮 token 数。
max_num_batched_tokens单轮处理的 token 预算单请求最大上下文。
max_model_len单序列上下文边界全服务所有请求 token 总和。
可用 KV 块状态是否有空间存放计算预算够就一定能运行。

Chunked prefill 的取舍

长 prompt 分多轮处理，可留预算给其他请求，减少长 prefill 对输出中请求的干扰；代价可能是长 prompt 的首 token 更晚。具体取舍依赖策略、预算、长度与执行成本。

教学模拟 · 不是源码逐行复刻

三个请求争用 token 预算

A：第 1 轮到达，prompt 6 / 输出 3；B：第 1 轮到达，prompt 2 / 输出 4；C：第 3 轮到达，prompt 3 / 输出 2。按到达顺序遍历，允许 chunked prefill；无 KV 上限、无抢占、无异步。prefill 完成即产生首输出。

如何映射到真实代码？

prompt 剩余量是未计算输入；生成计数对应 output_token_ids；配额对应 num_scheduled_tokens。真实实现还区分 running/waiting、KV 分配、优先级、推测、in-flight 与特定模型约束。轮数不是延迟基准。

KV 分页与前缀复用

迁移内存管理经验，保留关键差异

每请求预留最大上下文的连续 KV 区域会浪费显存。分页管理让请求按需领取固定 token 容量的物理块，维护逻辑块表。逻辑连续序列能放在不连续物理块里，由 Attention kernel 按块表寻址。

请求 A：10 tokens，block size=4
逻辑 0：t0…t3
↓ 物理块 7逻辑 1：t4…t7
↓ 物理块 2逻辑 2：t8,t9,空,空
↓ 物理块 9

块表 [7,2,9]，逻辑连续不要求物理连续。

logical_block = position // block_size
offset = position % block_size
physical_block = block_table[logical_block]

真实地址还涉及 layer/head/dtype/layout。尾块仍有内部碎片；减少连续分配浪费不代表零浪费。KV block 也不是 CUDA thread block。

前缀缓存缓存的是“条件计算”

相同 token 前缀可复用已算 KV，减少 prefill。块身份除块内 token，还需此前前缀身份，以及影响计算的适配器、多模态标识、salt 等信息。同一段文本接在不同前文之后，KV 可能不同。

先用完整块理解：block size=4，共享前 8 tokens 可复用两个块；分叉后分别计算。真实实现还有分组、对齐、局部命中和保留策略，不能把字符串匹配长度直接当作可跳过计算量。

每项性能优化到底省了什么

FlashAttention、编译、CUDA Graph 与采样

优化先找成本。GPU 善于大量并行算术，但显存搬运、CPU 启动小 kernel、跨卡通信都能使算力闲置。

机制降低的成本边界
FlashAttention 类实现分块/融合降低 Attention 中间结果的显存读写不替代请求调度或 KV 管理。
Paged KV降低每请求连续最大预留的浪费与 FlashAttention 不同，可以组合。
torch.compile / 融合解释执行、算子边界与中间张量开销首次编译、动态 shape 可能带来成本。
CUDA Graph重复提交 GPU 工作的 CPU 启动开销不缓存答案，每轮仍计算新输入。
量化权重/KV 存储与传输，部分硬件的算术成本依赖 kernel、shape、硬件，要验证质量。
时间下界 ≳ max(计算量 / 有效算力，搬运量 / 有效带宽)

这是忽略启动、通信等开销的估算。大 prefill 常更能摊薄权重读取并利用矩阵计算；小 batch decode 常受权重/KV 带宽或启动限制。上下文、并发与模型结构会改变瓶颈，别把“prefill 一定 compute-bound”当定律。

从一张 GPU 到多张

先问切什么，再问怎样通信

“模型太大”和“请求太多”是不同问题。前者需要分摊模型/状态，后者可能用多个副本扩吞吐。通信、同步、负载不均和网络拓扑都会进入成本。

方式如何拆收益成本
TP 张量并行同层矩阵/heads 分给多卡分摊单模型并协作计算层间频繁 collective，互联敏感。
PP 流水线并行不同层分到不同 stage分摊权重流水线气泡、stage 不均衡。
DP 数据并行模型副本处理不同请求扩整体吞吐每副本仍需放下模型；需均衡请求。
EP 专家并行MoE experts 分散到设备分摊专家参数与工作路由、all-to-all、热点。
CP 上下文并行长上下文相关计算/状态分摊更长序列或更高效率额外通信与后端组合限制。

常见稠密模型预算：GPU 数 = DP × PP × TP。8 卡、TP=2、PP=1、DP=4 意味四组副本，每组两卡协作。EP/CP 具体映射依实现，不能作为独立乘数随意相乘。

遇到术语，先找位置，再回到数据流。

AI Infra
支持训练、推理、部署的计算、存储、通信与软件系统。
Inference
用已经训练的参数计算输出。
Token
tokenizer 定义的编码单元，不等于字符或单词。
Tensor
带 shape、dtype 和设备归属的多维数组。
Prefill
计算 prompt 上下文状态并产生首个输出的阶段概念。
Decode
处理新输入 token 并产生后续输出的阶段概念。
KV Cache
每层历史位置的 Key/Value 中间状态。
Logits
归一化前的候选 token 分数。
Continuous batching
每轮动态加入/退出请求的批处理方式。
Chunked prefill
把长 prompt 的计算分散到多轮。
Block table
逻辑 KV 块到物理 KV 块的映射。
Prefix hit
复用相同前缀的条件计算。
Preemption
因资源/策略暂停请求，恢复可能需重算或恢复状态。
Kernel
设备上的计算程序，不是操作系统内核。
HBM
设备的高带宽显存。
CUDA Graph
重放 GPU 工作提交结构，减少发射开销。
Triton
编写高效 GPU kernel 的语言与编译工具。
TTFT
Time To First Token，首 token 延迟。
ITL
Inter-Token Latency，输出 token 间隔。
SLO
服务目标，如首 token 和尾延迟要求。
TP / PP / DP
张量并行 / 流水线并行 / 数据并行。
MoE
每个 token 路由到部分专家的网络。
GQA
多个 Q head 共享较少 KV head。
Quantization
降低表示/计算精度，需验证性能与质量。
Speculative decoding
草稿提出候选、目标模型验证的解码方法。
